# TV player feature delivery implementation plan

> For agentic workers: use superpowers:executing-plans; deliver each issue independently with TDD, a fresh branch review and GHA before merging.

**Goal:** Implement the eight approved future-improvement issues in order, ready for the owner's afternoon TV acceptance session.
**Architecture:** Extend the existing native player and bounded Luna service. Keep preferences/history local, metadata fresh and the decoder singular. Reuse existing validation, cancellation, remote navigation and localization.
**Tech stack:** ES5 browser scripts (Chromium 38+), service Node.js 0.12.2+, modern Node/npm build tooling.
**Spec:** GitHub issues #8–#15, approved for sequential delivery by the owner on 18 October 2026.

## Global constraints

- No TV power-on, deployment or device testing during implementation; device acceptance is deferred by explicit owner instruction.
- Preserve HTTPS validation, exact origin allowlists, decoded response limits, resource bounds, same application/service IDs and existing local data.
- All 13 locales cover new UI keys; no chat, account login, analytics, firmware/root changes or silent package installation.
- Candidate version 0.8.0, with no release opt-in file until TV acceptance. Each feature uses a separate PR, `npm test`, packaging/preflight and passing PR/main GHA.
- Keep issues open with implementation evidence while real-device acceptance remains outstanding. Do not claim mock/native equivalence.

## Review focus

- Changing channel/screen while async work finishes must not mount stale media or restore old focus.
- Denied/corrupt/full storage must not break navigation or store media credentials.
- Keyboard-only navigation, long translated strings and small layouts need explicit coverage.
- Recovery/quality/seek actions must preserve pause intent and cancel all obsolete timers/listeners.
- New metadata/update endpoints must remain fixed and validated, with bounded requests, bytes and cache lifetimes.

## Task sequence

1. #8 Continue watching: saved-position choice, bounded six-item home pages, two cancellable metadata workers, fresh public replay lookup, remove unavailable history. Test restart, near-end/completed/deleted/private items, denied storage and stale replies.
2. #9 Favorites: canonical bounded store, pin/remove/reorder with explicit move/cancel controls, independent recents/history and visible-only status checks. Test persistence, duplicates, full lists, paging and remote focus.
3. #10 Quality: validated rendition metadata, Auto/manual ceiling with preference persistence, position/pause-preserving remount; distinguish preference/source maximum from unavailable actual telemetry. Test missing renditions, failures and stale changes.
4. #11 Reconnect: bounded backoff, fresh validated source resolution, last replay position, visible-playing-only recovery and explicit retry after exhaustion. Test flapping, expired URLs and cancellation.
5. #12 Search/filter: local saved-channel/title queries, history filters, deterministic sort, six-card pages and clear loaded-subset copy. Test Unicode, empty results and Back/focus.
6. #13 Long seeks: explicit time entry and accelerated keys, target preview/confirm/cancel using existing serialized seek queue. Test boundaries, held keys, pause and disposal.
7. #14 Updates: About screen, fixed GitHub release metadata endpoint with bounded cached request, semantic versions, safe links/plain notes and supported manual installation guidance. Test offline/rate limits/malformed data and cancellations.
8. #15 Accessibility: persistent size/contrast preferences, consistent named focusable controls, semantic status updates and adaptive grids. Test all locales, focus and geometry; Voice Guide remains a device check.

For each task: write and observe meaningful failing tests, implement, run the whole suite and build, review, attest staged tree, commit/push, verify all PR GHA jobs, merge, verify main GHA and record evidence in its issue. Continue directly to the next task.

## Quality implementation ruling

LG's native HLS guidance requires a single-variant URL for fixed quality; initial bitrate and maxHeight are not a reliable adaptive ceiling. #10 therefore offers validated fixed renditions with an explicit Auto fallback, and disables choices with external/unknown audio groups to preserve sound. A future filtered master service could provide adaptive ceilings. DOM videoWidth is not used as decoder telemetry. References: https://webostv.developer.lge.com/develop/guides/mediaoption-parameter and https://forum.webostv.developer.lge.com/t/show-video-quality-options-and-enforce-a-quality-level-to-native-player/27930. Device behavior remains an afternoon acceptance check.
