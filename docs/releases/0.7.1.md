Adds legacy service-runtime compatibility for LG TVs using Node.js 0.12.2, including the LG UJ6307 (2017) / webOS 3.5 reported by **Claire**. Thanks to Claire for the detailed investigation. Fixes #2.

- Replaces unavailable `Array.from` in the service and UI while keeping complete emoji at title-length limits.
- Removes the dependency on WHATWG `url.URL`; playlist requests retain strict HTTPS host validation and preserve signed query escapes.
- Uses Unicode normalization when the TV provides it and retains readable original text otherwise.
- Retries a reset connection once using a fresh socket, avoiding stale keep-alive sockets on old Node versions.
- Adds a flexbox replay catalog fallback for engines without CSS Grid.
- Adds real Node.js 0.12.2 and 8.12.0 integration checks to CI.

**Validation:** full regression suite on Node.js 24.19.0; integration checks on actual Node.js 0.12.2 and 8.12.0; official `ares-package` build. Integration checks use local network streams and gzip, covering channels, public replays, statuses, HLS metadata, Unicode, signed URL escaping, rejected origins, response limits and transfer failures.

**Device verification:** no LG UJ6307 was available. Installation, live Kick TLS connectivity, native playback/seek and old-engine visual layout still need to be checked on webOS 3.5. This release fixes confirmed code incompatibilities; it does not claim completed hardware verification.

Install `cz.jirak.kicktv_0.7.1_all.ipk` with webOS Dev Manager. It includes both the app and its service, preserves the existing app ID and stored viewing history, and does not modify TV firmware. `SHA256SUMS` verifies the package.
