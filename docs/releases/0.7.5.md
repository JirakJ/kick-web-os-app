Fixes playback recovery and seek races, reduces timer churn, and bounds retained
UI and network resources. Includes the build-tool security fixes prepared in
0.7.4; 0.7.4 was tested locally but was not published.

- Preserve a newly entered seek target when resuming or recovering a decoder.
- Cancel a seek's debounce timer when native seek completion starts queued work,
  preventing orphan callbacks from committing later input early.
- Keep one stall watchdog and renew its deadline using a monotonic clock. A
  simulated minute with 240 progress events now allocates 3 timers instead of
  240, while still detecting a stall twenty seconds after the last progress.
- Detach retired videos before the final empty-source reset, remove every media
  listener, and avoid retaining old videos in unsettled play callbacks. Native
  stress testing caught the webOS teardown-order retention.
- Release replay cards and thumbnail references on return to the home screen.
- Cap idle HTTPS sockets at two across all media origins. A real-socket test
  over 25 CDN origins verifies the cap and same-origin keep-alive reuse.
- Add both resource integration tests to the Node.js 0.12.2 and 8.12.0 CI jobs.
- Require npm audit and a checksum-verified, pinned Gitleaks history scan in CI;
  publication runs only after every main-branch CI job succeeds.

The application and service identity remain `com.jakubjirak` and
`com.jakubjirak.service`. Updates from 0.7.2 or newer preserve their stored data.
Download `com.jakubjirak_0.7.5_all.ipk` and verify the attached `SHA256SUMS`.

Validation and device measurements are recorded in the
[production audit](https://github.com/JirakJ/kick-web-os-app/blob/main/docs/production-audit.md).
Resource limits and bounded stress tests are not a guarantee against every
browser, decoder or firmware leak, and multi-hour playback remains unverified.
